The dependency policy tests reject the old PDF.js runtime/worker references and verify every shipped library/data file against vendor/UPSTREAM.json. Official npm tarballs were checked against registry SHA512 before extraction; SheetJS 0.20.3 comes from its primary distribution site because npm stops at vulnerable 0.18.5. Original upstream licenses are retained beside the runtime files.

PDF.js 6.4.299 initializes lazily as ESM over HTTP with its matching module worker, CMaps, standard fonts, WASM and ICC data from the same package. Every document load sets isEvalSupported:false as defense in depth. For direct file URLs, generated IIFE bridges from those exact ESM sources retain the main-thread-worker fallback without depending on module imports. Rebuild with `ESBUILD_MODULE=/absolute/esbuild/lib/main.js node scripts/build-pdf-file-bridge.mjs` using esbuild 0.28.2 and update generated file hashes.

Validation: real Chromium loads/renders a two-page PDF, extracts its known text, and uses the matching worker. Viewer was compared on file:// before/after the migration, both rendering two pages while all external network requests were blocked. HTTP rendering was also validated. The static files remain self-hostable without a package manager or a build command.
